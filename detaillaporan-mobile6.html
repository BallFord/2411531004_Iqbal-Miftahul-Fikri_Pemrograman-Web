Arsitektur Navigasi Named Routes & Bottom Navigation Bar dan Pembuatan Aplikasi Expense Tracker

Dokumentasi Praktikum Navigasi dan Project Expense Tracker pada Framework Flutter

Kembali ke Halaman Report

A. Pendahuluan

Perkembangan teknologi informasi membuat penggunaan aplikasi semakin dibutuhkan dalam kehidupan sehari-hari, termasuk untuk mengelola keuangan pribadi. Pencatatan pemasukan dan pengeluaran secara manual terkadang menyulitkan pengguna ketika ingin mengetahui jumlah transaksi yang telah dilakukan. Oleh karena itu, diperlukan aplikasi yang dapat membantu pengguna mencatat transaksi, menyimpan data, dan melihat riwayat keuangan dengan lebih mudah. Pada Project Praktikum 5 ini, dikembangkan aplikasi Expense Tracker menggunakan Flutter sebagai framework pengembangan antarmuka aplikasi dan SQLite sebagai database lokal untuk menyimpan informasi pengguna serta transaksi keuangan.

Project ini merupakan penggabungan materi dari Modul Praktikum 1 sampai Modul Praktikum 5 ke dalam satu aplikasi yang saling terhubung. Aplikasi dilengkapi dengan halaman login, registrasi akun, dashboard, penambahan transaksi, riwayat transaksi, detail transaksi, dan profil pengguna. SQLite digunakan agar data dapat disimpan secara lokal pada perangkat, sedangkan Flutter digunakan untuk membangun tampilan dan mengatur interaksi antarlayar. Melalui project ini, materi praktikum diterapkan dalam bentuk aplikasi yang memiliki struktur lebih terorganisasi dan dapat diuji secara langsung.

B. Tujuan

Tujuan dari praktikum ini adalah:

  • Memahami penerapan framework Flutter dalam membangun aplikasi dengan antarmuka yang interaktif.
  • Menerapkan penggunaan widget, form, validasi input, navigasi halaman, dan pengelolaan state pada aplikasi.
  • Mengimplementasikan database lokal SQLite untuk menyimpan data pengguna dan transaksi keuangan.
  • Menggabungkan materi Praktikum 1 sampai 5 menjadi aplikasi Expense Tracker yang memiliki fitur login, registrasi, dashboard, pencatatan transaksi, riwayat, dan profil pengguna.
  • Menguji fungsionalitas aplikasi untuk memastikan proses registrasi, login, penyimpanan transaksi, dan pengambilan data berjalan sesuai kebutuhan.

C. Langkah-Langkah

Arsitektur Navigasi

1. Mendaftarkan Named Routes.

Buka file main.dart. Hapus parameter home pada MaterialApp, lalu ganti dengan initialRoute dan routes.

Kode ini berfungsi untuk mengatur arsitektur navigasi terpusat berbasis Named Routes pada aplikasi Flutter dengan mengganti deklarasi tunggal home menggunakan initialRoute dan tabel routes. Properti initialRoute: '/' menentukan halaman awal yang langsung dimuat saat aplikasi dibuka, yaitu MainScreen, sementara peta routes mendaftarkan alamat rute unik seperti '/add' yang terhubung ke AddTransactionScreen agar proses perpindahan layar dapat dipanggil dengan rapi dan konsisten menggunakan Navigator.pushNamed.

2. Membuat Penampung Tab (MainScreen).

Buat file main_screen.dart. Jadikan halaman ini sebagai StatefulWidget karena tab yang aktif akan selalu berubah nilainya.

Kode ini bertugas mengelola status penentuan halaman aktif pada menu navigasi bawah menggunakan variabel _selectedIndex dan daftar widget _pages yang merepresentasikan setiap tampilan layar. Ketika pengguna mengetuk salah satu item menu navigasi, fungsi _onItemTapped akan dijalankan untuk memperbarui nilai _selectedIndex di dalam perintah setState, sehingga antarmuka Flutter secara otomatis memperbarui tampilan utama sesuai dengan halaman yang dipilih.

3. Merangkai BottomNavigationBar.

Lengkapi method build di MainScreen dengan Scaffold dan BottomNavigationBar untuk menghubungkan halaman Beranda, Riwayat, dan Profil.

Kode ini bertugas membangun struktur tampilan utama aplikasi menggunakan Scaffold, di mana komponen body menampilkan halaman dari daftar _pages sesuai dengan indeks tab yang sedang dipilih. Properti bottomNavigationBar membentuk navigasi di bagian bawah dengan tiga item, yang mengaitkan fungsi _onItemTapped saat tombol diketuk untuk mengubah posisi currentIndex serta memberi sorotan warna amber pada ikon yang aktif.

Latihan/Tugas
  • Buat halaman riwayat transaksi.
  • Buat halaman profil yang berisi avatar, nama, email, dan tombol logout.
  • Buat halaman login yang berisi text field email dan password serta tombol login. Setelah login, tampilkan halaman utama dan informasi email pengguna.

5. Halaman Riwayat Transaksi (history_screen.dart).

Halaman ini menggunakan ListView untuk menampilkan daftar transaksi statis.

Kode ini membangun tampilan layar HistoryScreen berjenis StatelessWidget yang digunakan untuk menyajikan daftar riwayat transaksi secara berulang menggunakan widget ListView.builder. Antarmuka ini dilengkapi dengan AppBar berwarna amber berjudul "Riwayat Transaksi" serta menampilkan lima baris daftar, di mana setiap item memuat ikon koin amber, judul transaksi dinamis berdasarkan nomor indeks, tanggal transaksi, dan nominal pengeluaran bernilai negatif dengan cetak tebal berwarna merah.

6. Halaman Profil (profile_screen.dart).

Kode ini membuat tampilan layar profil pengguna berjenis StatelessWidget yang menampilkan avatar lingkaran, nama pengguna "Iqbal Miftahul Fikri", serta alamat email yang diterima dari proses login. Antarmuka ini disusun secara vertikal di tengah layar menggunakan widget Column di dalam Scaffold berbalut AppBar, serta dilengkapi tombol Logout yang memanfaatkan perintah Navigator.pushNamedAndRemoveUntil untuk mengembalikan pengguna ke halaman login sekaligus menghapus seluruh tumpukan riwayat navigasi sebelumnya.

7. Halaman Login (login_screen.dart).

Kode ini mengimplementasikan layar login berjenis StatefulWidget yang bertugas menangkap input pengguna melalui dua bidang TextField menggunakan TextEditingController. Antarmuka ini disusun rapi di dalam Scaffold dengan ikon dompet dan judul "Login Aplikasi", serta menyediakan tombol "LOGIN" yang saat ditekan akan mengambil teks email pengguna dan mengarahkannya ke halaman utama menggunakan Navigator.pushReplacement untuk mengirim data email sekaligus menggantikan halaman login dari tumpukan navigasi.

Project Praktikum 5

Pada praktikum ini dibuat aplikasi sederhana yang menggabungkan materi dari Modul Praktikum 1 sampai 5.

9. Persiapan Project Flutter.

Tahap pertama adalah menyiapkan project Flutter sebagai dasar pengembangan aplikasi. Project dibuat dan dijalankan menggunakan Visual Studio Code atau Android Studio dengan perangkat Android sebagai target pengujian. Struktur file disusun agar setiap halaman memiliki file tersendiri, misalnya main.dart, login_screen.dart, register_screen.dart, dashboard_screen.dart, add_transaction_screen.dart, history_screen.dart, profile_screen.dart, transaction_detail_screen.dart, dan database_helper.dart.

10. Menambahkan Dependensi.

Tahap berikutnya adalah menambahkan dependensi yang diperlukan untuk mengembangkan aplikasi. Dependensi yang digunakan meliputi sqflite untuk mengakses database SQLite, path untuk menyusun lokasi file database, dan bcrypt untuk melakukan pemeriksaan hash password pengguna.

11. Membuat Database Lokal SQLite.

Buat file database_helper.dart untuk mengelola database lokal aplikasi. File ini berfungsi membuka database, membuat tabel, menyimpan data pengguna, mengambil data transaksi, memperbarui transaksi, menghapus transaksi, dan menghitung total pengeluaran. Database yang digunakan bernama catatan_keuangan.db, dengan dua tabel utama, yaitu users dan transactions.

Kode berikut merupakan bagian utama untuk membuka database dan membuat tabel:

Tabel users digunakan untuk menyimpan identitas pengguna, seperti nama, email, dan hash password. Sementara itu, tabel transactions digunakan untuk menyimpan data transaksi berupa judul, nominal, kategori, tanggal, dan ID pengguna yang melakukan transaksi. Kolom user_id menghubungkan transaksi dengan akun pemiliknya sehingga setiap pengguna dapat memiliki data transaksi masing-masing. Pengaturan PRAGMA foreign_keys = ON digunakan untuk mengaktifkan pemeriksaan relasi antartabel.

13. Menginisialisasi Database pada main.dart.

Tahap berikutnya adalah menghubungkan database dengan aplikasi melalui file main.dart. Flutter perlu diinisialisasi sebelum database dibuka dan aplikasi dijalankan menggunakan runApp().

Fungsi WidgetsFlutterBinding.ensureInitialized() memastikan Flutter siap sebelum proses inisialisasi database dilakukan. Lalu, DatabaseHelper.instance.database digunakan untuk membuka database dan membuat tabel apabila database belum tersedia. Properti initialRoute menentukan bahwa aplikasi pertama kali menampilkan halaman login, sedangkan routes digunakan untuk mengarahkan navigasi menuju halaman tertentu.

14. Membuat Halaman Registrasi Akun.

Halaman registrasi dibuat melalui file register_screen.dart. Halaman ini digunakan oleh pengguna baru untuk memasukkan nama, email, dan password sebelum dapat masuk ke aplikasi. Data yang diisi kemudian divalidasi dan disimpan ke tabel users melalui fungsi insertUser(). Contoh bagian inti proses registrasi:

Fungsi tersebut memperlihatkan proses inti penyimpanan akun, yaitu membersihkan input nama dan email, mengubah email menjadi huruf kecil, membuat hash password, lalu menyimpan data pengguna ke database. Password tidak disimpan sebagai teks biasa, melainkan sebagai hash yang nantinya digunakan untuk memeriksa password ketika login. Di kode lengkapnya, fungsi ini dipanggil dari tombol registrasi setelah semua input dinyatakan valid. Jika email sudah digunakan, proses penyimpanan perlu ditangani agar aplikasi dapat memberikan pesan yang sesuai.

15. Membuat Halaman Login.

Halaman login dibuat melalui file login_screen.dart. Halaman ini berfungsi memeriksa email dan password yang dimasukkan pengguna. Data akun dicari berdasarkan email menggunakan getUserByEmail(), kemudian password diperiksa menggunakan BCrypt.checkpw(). Jika akun ditemukan dan password sesuai, pengguna diarahkan ke halaman utama dengan membawa data email dan ID pengguna. Berikut bagian utama fungsi login berdasarkan implementasi yang telah digunakan:

Fungsi login() melakukan validasi input sebelum mengakses database. Jika email tidak ditemukan, aplikasi menampilkan pesan bahwa akun belum terdaftar. Jika email ditemukan, password yang dimasukkan dibandingkan dengan hash yang tersimpan. Apabila pemeriksaan berhasil, pengguna diarahkan ke MainScreen dengan membawa ID pengguna dan email. Data tersebut diperlukan agar halaman berikutnya dapat menampilkan informasi pengguna yang sesuai dan mengakses transaksi milik akun yang sedang login.

16. Membuat Halaman Utama dan Navigasi.

Setelah login berhasil, pengguna diarahkan ke halaman utama yang dibuat pada file main_screen.dart. Halaman ini menggunakan BottomNavigationBar untuk menghubungkan tiga bagian aplikasi, yaitu Beranda, Riwayat, dan Profil. ID pengguna dan email diteruskan ke halaman yang memerlukan informasi akun.

Kode ini menunjukkan struktur utama navigasi aplikasi. Variabel _selectedIndex digunakan untuk menentukan halaman yang sedang ditampilkan, sedangkan fungsi _onItemTapped() mengubah halaman ketika pengguna memilih menu di bagian bawah layar. Data userId diteruskan ke halaman dashboard dan riwayat agar kedua halaman dapat mengambil transaksi milik pengguna yang sedang login. Data email juga diteruskan ke halaman profil. Pada kode final atau yang sudah jadi, nilai Nama Pengguna perlu diganti dengan nama pengguna yang diambil dari database agar setiap akun menampilkan nama yang benar.

17. Membuat Dashboard Keuangan.

Dashboard dibuat melalui file dashboard_screen.dart. Halaman ini menjadi tampilan utama setelah pengguna login. Dashboard menampilkan sapaan pengguna, kartu saldo, daftar transaksi terakhir, dan tombol tambah transaksi. Tombol tambah transaksi menggunakan navigasi bernama /add untuk membuka formulir pencatatan transaksi.

Berikut struktur utama dashboard:

Dashboard digunakan sebagai pusat informasi keuangan pengguna. Bagian sapaan menampilkan nama pengguna, kartu saldo menampilkan informasi saldo, sedangkan bagian transaksi terakhir digunakan untuk melihat transaksi yang baru dilakukan. Tombol dengan ikon tambah memudahkan pengguna membuka halaman pencatatan transaksi. Kode ini menyederhanakan bagian daftar transaksi sebagai contoh struktur. Di akhir, bagian tersebut harus diganti dengan _buildTransactionList() agar sesuai dengan tampilan dan perilaku aplikasi yang benar-benar dijalankan.

18. Membuat Formulir Tambah Transaksi.

Formulir penambahan transaksi dibuat melalui file add_transaction_screen.dart. Halaman ini menyediakan input judul transaksi, nominal, kategori, dan tanggal.

Kode ini menunjukkan struktur formulir dan validasi data transaksi. Judul tidak boleh kosong, nominal harus berupa angka bulat positif, kategori dipilih melalui dropdown, dan tanggal dipilih menggunakan showDatePicker(). Namun, pada contoh di atas, tombol simpan baru menampilkan notifikasi dan menutup halaman. Agar transaksi benar-benar tersimpan, kode final harus memanggil DatabaseHelper.instance.insertTransaction() sebelum menampilkan pesan berhasil.

Proses Penyimpanan Transaksi ke SQLite.

Bagian penting pada project ini adalah menghubungkan tombol simpan dengan database. Contoh ini memperlihatkan inti proses penyimpanan transaksi.

Kode ini memasukkan data transaksi ke tabel transactions. Kolom user_id digunakan untuk menghubungkan transaksi dengan akun yang sedang login. Dengan demikian, data transaksi tidak hanya ditampilkan melalui notifikasi, tetapi juga disimpan dalam database lokal. Pada kode final, kode penyimpanan perlu ditempatkan dalam fungsi async pada tombol simpan, setelah validasi form berhasil dilakukan.

19. Membuat Halaman Riwayat Transaksi.

Halaman riwayat dibuat melalui file history_screen.dart. Halaman ini digunakan untuk menampilkan daftar transaksi yang sudah dilakukan pengguna. Data transaksi diambil berdasarkan ID pengguna agar setiap akun hanya melihat transaksi miliknya sendiri. Contoh inti pengambilan data transaksi:

Kode tersebut merupakan contoh implementasi riwayat yang membaca data dari SQLite menggunakan getTransactions(). FutureBuilder digunakan untuk menangani proses pemuatan data, menampilkan indikator ketika data sedang diambil, dan menampilkan pesan jika belum ada transaksi. Apabila transaksi tersedia, data ditampilkan melalui ListView.builder(). Dengan pendekatan ini, halaman riwayat dapat menampilkan data yang benar-benar tersimpan, bukan sekadar data contoh yang ditulis secara langsung di dalam kode.

20. Membuat Halaman Detail Transaksi.

Halaman detail transaksi dibuat melalui file transaction_detail_screen.dart. Halaman ini digunakan untuk menampilkan informasi satu transaksi secara lebih lengkap, seperti judul, nominal, kategori, tanggal, dan status. Data transaksi dikirim melalui parameter constructor sehingga halaman detail dapat menampilkan informasi sesuai transaksi yang dipilih pengguna.

Pada kode ini, TransactionDetailScreen menggunakan StatelessWidget karena halaman hanya menerima data yang dibutuhkan dan tidak mengelola perubahan state internal. Constructor dengan parameter required memastikan data yang dibutuhkan tersedia ketika halaman dibuka. Fungsi _buildDetailRow() digunakan untuk membuat baris informasi agar tampilan kategori, tanggal, dan status lebih teratur. Halaman ini dapat dibuka dari daftar transaksi melalui navigasi ketika pengguna memilih salah satu transaksi.

21. Membuat Halaman Profil Pengguna.

Halaman profil dibuat melalui file profile_screen.dart. Halaman ini digunakan untuk menampilkan informasi akun pengguna, terutama nama dan email. Data tersebut diteruskan dari halaman utama menggunakan parameter userName dan userEmail.

23. Pengujian Aplikasi.

Setelah seluruh halaman dan fungsi utama dihubungkan, lakukan pengujian untuk memastikan aplikasi berjalan dengan baik. Pengujian dilakukan pada perangkat Android melalui lingkungan pengembangan Flutter. Pemeriksaan meliputi proses registrasi, login, navigasi halaman, penambahan transaksi, pengambilan riwayat, dan penampilan profil pengguna.

Pengujian dilakukan dengan membuat akun baru, melakukan login menggunakan akun tersebut, membuka dashboard, dan mencoba fitur yang tersedia. Pengujian dua akun juga digunakan untuk memeriksa apakah data pengguna dapat dibedakan. D. Kesimpulan

Berdasarkan pengerjaan Project Praktikum 5, dapat disimpulkan bahwa materi dari Modul Praktikum 1 sampai 5 dapat digabungkan menjadi sebuah aplikasi pencatatan keuangan berbasis Flutter. Aplikasi Expense Tracker dirancang dengan beberapa halaman utama, yaitu registrasi akun, login, dashboard, penambahan transaksi, riwayat transaksi, detail transaksi, dan profil pengguna. Penggunaan widget, form, validasi input, navigasi, serta pengelolaan state membantu membangun aplikasi yang lebih terstruktur dan mudah digunakan. Sementara itu, penggunaan SQLite menyediakan penyimpanan lokal untuk data akun dan transaksi.

Melalui project ini, pemahaman mengenai pengembangan aplikasi Flutter dapat diterapkan secara langsung, mulai dari penyusunan antarmuka hingga pengelolaan data menggunakan database lokal. Fungsi autentikasi membantu membedakan akun pengguna, sedangkan struktur tabel dan relasi database memungkinkan transaksi dikaitkan dengan pemiliknya. Pengujian melalui perangkat Android dan pemeriksaan kode menggunakan Flutter Analyzer juga membantu memastikan kesiapan aplikasi. Dengan demikian, project ini menjadi penerapan materi praktikum dalam bentuk aplikasi yang menggabungkan antarmuka, navigasi, validasi, dan penyimpanan data lokal dalam satu sistem.
