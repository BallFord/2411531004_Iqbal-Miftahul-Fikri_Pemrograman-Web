State Management pada Aplikasi ResepKu

Dokumentasi Praktikum Pengelolaan State Ephemeral dan Global Menggunakan Provider pada Framework Flutter

Kembali ke Halaman Report

A. Pendahuluan

Pengembangan aplikasi mobile modern dengan Flutter membutuhkan pengelolaan state yang terstruktur untuk memastikan antarmuka pengguna dapat bereaksi secara dinamis terhadap perubahan data. Dalam Flutter, state terbagi menjadi dua kategori utama, yaitu ephemeral state (state lokal) dan app state (state global). Ephemeral state yang umumnya dikelola menggunakan method setState() sangat efektif untuk data sementara yang terisolasi di dalam satu widget. Namun, ketika data perlu dibagikan atau diperbarui secara lintas halaman, penggunaan state lokal menjadi sangat terbatas dan kurang efisien.

Untuk mengatasi keterbatasan tersebut, praktikum ini berfokus pada pengimplementasian app state menggunakan paket Provider dengan arsitektur ChangeNotifier pada aplikasi ResepKu. Melalui praktikum ini, dilakukan eksplorasi mendalam mengenai pengelolaan state global untuk mengelola daftar resep favorit serta konfigurasi preferensi tema aplikasi. Selain itu, praktikum ini menguji pentingnya pemahaman hierarki widget tree dan posisi peletakan provider agar data dapat diakses secara konsisten oleh seluruh rute halaman tanpa memicu error ProviderNotFoundException.

B. Tujuan

Tujuan dari praktikum ini adalah:

  • Memahami perbedaan mendasar antara ephemeral state (state lokal) dan app state (state global) serta penentuan situasi penggunaannya di Flutter.
  • Mengimplementasikan pengelolaan data terpusat menggunakan Provider dan ChangeNotifier untuk fitur daftar resep favorit pada aplikasi ResepKu.
  • Menganalisis pengaruh posisi peletakan ChangeNotifierProvider dalam widget tree terhadap akses BuildContext saat navigasi rute halaman.
  • Membangun fitur pengubah tema aplikasi secara global menggunakan ThemeProvider yang terintegrasi langsung dengan MaterialApp.
  • Mengembangkan interaksi antarmuka yang dinamis, mencakup pembaruan ikon favorit, pembaruan badge angka secara real-time, hingga fitur hapus semua favorit yang dilengkapi dialog konfirmasi.

6. Langkah B.1 — Mengganti RecipeTile

7. Langkah B.2 — Mengamati hasilnya

Lakukan hot reload. Tap ikon hati pada dua resep.

  • Apakah ikon hati berubah? Mengapa?
    Ya, ikon hati berubah bentuk dan warna saat ditekan. Hal ini terjadi karena RecipeTile dibuat menggunakan StatefulWidget, dan pemanggilan setState() pada tombol me-rebuild widget RecipeTile secara lokal sehingga variabel isFavorite diperbarui nilainya.
  • Coba tampilkan jumlah resep favorit di judul AppBar HomePage. Apakah hal itu dapat dilakukan? Di class mana data _isFavorite berada, dan apakah HomePage dapat membacanya?
    Tidak dapat dilakukan secara langsung. Variabel _isFavorite berada di dalam class _RecipeTileState yang bersifat private dan terisolasi sebagai child widget. Oleh karena itu, HomePage tidak memiliki akses untuk membaca atau menjumlahkan nilai _isFavorite dari tiap-tiap tile.
  • Buka halaman detail dari resep yang sudah difavoritkan. Bagaimana halaman detail dapat mengetahui bahwa resep tersebut favorit?
    Halaman detail (DetailPage) tidak dapat mengetahui status favorit tersebut. Hal ini terjadi karena status _isFavorite tersimpan secara lokal di dalam _RecipeTileState, sedangkan saat berpindah ke DetailPage, data yang dikirimkan hanyalah objek Recipe tanpa membawa informasi state lokal dari RecipeTile.

Pertanyaan Analisis

15. Tuliskan jawaban tiga pertanyaan pada Langkah B.2, lengkap dengan alasannya.

Ikon hati pada RecipeTile dapat berubah bentuk dan warna menjadi merah saat ditekan karena menggunakan StatefulWidget yang memanggil setState() secara lokal pada widget tersebut. Namun, jumlah favorit tidak dapat ditampilkan di AppBar HomePage karena variabel _isFavorite berada di dalam class _RecipeTileState yang terisolasi dan tidak dapat dibaca oleh HomePage. Keterbatasan state lokal ini juga menyebabkan DetailPage tidak dapat mengetahui status favorit suatu resep, karena navigasi hanya mengirimkan objek Recipe tanpa membawa data _isFavorite dari RecipeTile.

16. Mengapa jumlah porsi tetap menggunakan setState() dan tidak dimasukkan ke Provider? Hubungkan jawaban kalian dengan hasil skenario 6 pada Langkah C.7.

Jumlah porsi tetap menggunakan setState() karena data tersebut bersifat ephemeral state (state lokal) yang hanya dibutuhkan secara sementara oleh DetailPage dan tidak perlu diakses oleh widget atau halaman lain. Hal ini sejalan dengan hasil eksperimen pada skenario 6 Langkah C.7, di mana ketika porsi diubah lalu pengguna kembali ke HomePage, widget DetailPage beserta state lokal _servings akan otomatis dibuang dari memori sehingga porsi kembali ke nilai awal saat resep dibuka lagi. Perilaku reset porsi ini sudah sesuai dengan kebutuhan aplikasi, sehingga tidak perlu dimasukkan ke dalam Provider yang diperuntukkan bagi app state global yang harus bertahan di banyak halaman.

Ketika ChangeNotifierProvider dipindahkan dari main() ke dalam HomePage untuk membungkus Scaffold, aplikasi mengalami error ProviderNotFoundException saat halaman Favorit Saya dibuka. Hal ini terjadi karena proses navigasi Navigator.push menempatkan FavoritePage sebagai route baru pada tingkatan widget tree yang berdiri sendiri dan tidak berada di bawah subtree HomePage. Karena FavoriteProvider hanya dideklarasikan secara lokal di dalam HomePage, maka FavoritePage tidak dapat mengakses provider tersebut dari BuildContext-nya.

D. Kesimpulan

Berdasarkan praktikum dan analisis yang telah dilakukan, dapat disimpulkan bahwa pemilihan metode state management yang tepat sangat berpengaruh terhadap performa dan arsitektur aplikasi. Penggunaan setState() terbukti ideal untuk ephemeral state yang relevansinya terbatas pada satu layar saja, seperti jumlah porsi pada halaman detail yang otomatis ter-reset saat halaman ditutup. Sebaliknya, penggunaan paket Provider sangat tepat untuk mengelola app state seperti data resep favorit dan mode tema aplikasi, sehingga perubahan data di satu komponen dapat langsung me-render ulang UI di komponen lain secara real time.

Praktikum ini juga membuktikan betapa krusialnya pemahaman hierarki widget tree dalam Flutter. Penempatan ChangeNotifierProvider di tingkat paling atas (membungkus MaterialApp) merupakan syarat utama agar state global dapat diakses oleh seluruh rute layar baru yang dipanggil melalui Navigator.push. Dengan penerapan arsitektur provider yang benar, aplikasi ResepKu berhasil berjalan dengan modular, interaktif, responsif, dan bebas dari kendala akses context.
