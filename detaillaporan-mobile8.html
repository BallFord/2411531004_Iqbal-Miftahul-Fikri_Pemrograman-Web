List, Grid, Gambar, dan Asset pada ResepKu

Dokumentasi Praktikum Integrasi Asset Lokal, Pemuatan Gambar Jaringan, Lazy Loading List & Grid, serta Optimasi Memori pada Framework Flutter

Kembali ke Halaman Report

A. Pendahuluan

Pengembangan aplikasi mobile menuntut penyajian data dan elemen visual yang tidak hanya menarik secara estetika, tetapi juga efisien dalam penggunaan sumber daya perangkat. Pada aplikasi ResepKu, daftar item yang disertai foto beresolusi tinggi dapat membebani memori dan menurunkan kelancaran scrolling apabila tidak dikelola dengan teknik lazy rendering serta optimasi gambar yang tepat. Oleh karena itu, pemahaman mengenai manajemen asset lokal, pemuatan gambar dari jaringan secara asinkron, dan pemilihan tata letak daftar maupun grid menjadi fondasi penting dalam membangun antarmuka Flutter yang responsif.

Pada Praktikum Aplikasi Mobile Modul 7 ini, pembahasan difokuskan pada integrasi asset lokal (logo, gambar placeholder, dan font Poppins) serta penerapan komponen ListView.builder, ListView.separated, dan GridView.builder pada aplikasi ResepKu. Praktikum ini juga mencakup pembuatan widget RecipeImage dengan penanganan status pemuatan (loadingBuilder), penanganan kegagalan koneksi (errorBuilder), serta efisiensi memori melalui parameter cacheWidth. Selain itu, fungsionalitas aplikasi diperluas melalui implementasi filter kategori masakan menggunakan ChoiceChip, fitur hapus geser (Dismissible) pada halaman favorit, serta efek foto menyusut saat digulir pada halaman detail menggunakan CustomScrollView dan SliverAppBar.

B. Tujuan

Tujuan dari praktikum ini adalah:

  • Mampu mengonfigurasi dan menampilkan asset lokal berupa gambar logo, placeholder, serta font kustom pada proyek Flutter melalui file pubspec.yaml.
  • Mampu mengimplementasikan pemuatan gambar dari jaringan (Image.network) yang dilengkapi indikator proses muat (loadingBuilder), penanganan kesalahan (errorBuilder), serta optimasi memori menggunakan parameter cacheWidth.
  • Mampu membangun tampilan daftar dan kisi secara efisien menggunakan ListView.builder, ListView.separated, dan GridView.builder serta mengelola pergantian mode tampilan secara dinamis.
  • Mampu menerapkan interaktivitas pada daftar data berupa penyaringan kategori (cuisine) menggunakan ChoiceChip dan penghapusan item dengan gestur geser (Dismissible) berbasis ValueKey.
  • Mampu merancang tata letak halaman detail yang responsif menggunakan CustomScrollView, SliverAppBar, dan package cached_network_image untuk menyimpan cache gambar pada perangkat.

C. Langkah-Langkah

Bagian A — Asset Gambar dan Custom Font

1. Langkah A.1 — Menyiapkan folder assets

Di folder utama project, buat folder assets beserta dua subfolder. Bisa melalui Explorer VS Code, atau melalui terminal.

2. Langkah A.2 — Mendaftarkan asset dan font di pubspec.yaml

Buka pubspec.yaml. Cari bagian flutter: di bagian bawah file, lalu ubah sehingga menjadi seperti berikut.

Langkah ini bertujuan mendaftarkan berkas gambar dan font kustom ke dalam berkas konfigurasi pubspec.yaml agar dapat dibaca oleh proyek Flutter. Baris assets/images/ berfungsi memasukkan seluruh gambar di dalam folder tersebut ke dalam bundel aplikasi, sementara bagian fonts mendaftarkan nama keluarga font (Poppins) beserta pemetaan tingkat ketebalannya (weight 500 untuk Medium dan 700 untuk Bold) berdasarkan berkas yang diletakkan pada folder assets/fonts/.

Setelah itu, jalankan flutter pub get pada terminal.

3. Langkah A.3 — Memasang font di tema aplikasi

Di lib/main.dart, tambahkan fontFamily pada theme dan darkTheme di MaterialApp.

Pada kode ini, atribut fontFamily: 'Poppins' ditambahkan ke dalam konfigurasi theme dan darkTheme pada MaterialApp untuk menerapkan font kustom Poppins secara global ke seluruh elemen teks aplikasi, baik pada mode terang maupun mode gelap, tanpa mengganggu integrasi ThemeProvider dan IdentityFooter yang telah dikonfigurasi sebelumnya.

4. Langkah A.4 — Logo di AppBar

Di lib/pages/home_page.dart, ganti parameter title pada AppBar menjadi Row berisi logo dan teks.

Checkpoint 1

Pada Checkpoint 1 ini, aplikasi ResepKu berhasil mengintegrasikan asset gambar lokal dan custom font yang telah didaftarkan pada pubspec.yaml ke dalam antarmuka aplikasi. Penggunaan Image.asset pada AppBar berhasil menampilkan logo di samping judul aplikasi, sementara penerapan fontFamily: 'Poppins' pada ThemeData secara global mengubah seluruh tipografi teks aplikasi ke font Poppins tanpa mengganggu komponen utama lain seperti footer identitas mahasiswa.

Bagian B — ListView.builder dan Foto Resep

5. Langkah B.1 — Membuat widget RecipeImage

Kode ini merupakan widget reusable berbasis StatelessWidget yang mengontrol proses pemuatan gambar jaringan secara aman dan efisien di seluruh aplikasi. Menggunakan Image.network, widget ini menangani tiga kondisi utama, yaitu menampilkan indikator loading berupa ikon menu restoran saat unduhan berlangsung via loadingBuilder, menampilkan gambar cadangan lokal via errorBuilder saat koneksi terputus atau URL gagal diakses, serta mengoptimalkan penggunaan memori RAM perangkat dengan opsi pemotongan skala resolusi gambar melalui parameter cacheWidth.

6. Langkah B.2 — Thumbnail di RecipeTile

Ganti seluruh isi recipe_tile.dart. Perubahannya hanya pada leading: CircleAvatar diganti foto berukuran 56 x 56 dengan sudut membulat.

Kode ini mendefinisikan widget RecipeTile berbasis StatelessWidget yang menampilkan item resep dalam bentuk daftar. Widget ini menggunakan ClipRRect dan RecipeImage berukuran 56 x 56 dp dengan cacheWidth: 168 untuk menampilkan gambar thumbnail bersudut membulat secara efisien dari segi penggunaan memori. Selain itu, widget ini memanfaatkan Provider yang berguna untuk mengelola status ikon favorit secara real time, serta menyediakan fungsi onTap untuk mengarahkan pengguna ke halaman DetailPage saat baris resep ditekan.

7. Langkah B.3 — ListView.builder di HomePage

Ganti seluruh isi home_page.dart dengan versi berikut: body yang sebelumnya ListView(children: [...]) diganti ListView.builder.

Kode ini dan hasil tampilan aplikasinya menunjukkan penerapan ListView.builder untuk menyusun daftar resep secara efisien melalui mekanisme lazy loading, di mana elemen RecipeTile hanya dibuat saat dirender di area layar. Pada tampilan antarmuka, setiap baris resep kini dilengkapi dengan thumbnail foto dari internet yang tampil rapi di sebelah nama dan detail resep, sambil tetap mempertahankan komponen lainnya.

8. Langkah B.4 — Menguji error state

Uji apa yang terjadi jika foto gagal dimuat.

Terlihat pada resep pertama (Classic Margherita Pizza), foto dari internet gagal dimuat karena URL yang diubah menjadi salah (1.webpX), sehingga widget RecipeImage melalui errorBuilder secara otomatis menampilkan gambar placeholder lokal. Sementara itu, resep lainnya tetap menampilkan foto dengan normal.

Checkpoint 2

Pada Checkpoint 2 ini, aplikasi ResepKu berhasil mengimplementasikan lazy loading daftar resep menggunakan ListView.builder yang terintegrasi dengan widget kustom RecipeImage. Penggunaan RecipeImage berbasis Image.network tidak hanya menampilkan thumbnail foto resep berukuran 56 x 56 dp secara efisien melalui pembatasan cacheWidth: 168, tetapi juga menyediakan penanganan loading state saat unduhan berlangsung serta error state yang secara otomatis mengalihkan tampilan ke gambar placeholder lokal jika koneksi terputus atau URL gambar tidak valid, tanpa mengganggu hal lainnya.

Bagian C — GridView dan Tombol Ganti Tampilan

9. Langkah C.1 — Membuat RecipeGridCard

Buat file baru untuk kartu grid dengan nama recipe_grid_card.dart

Kode ini mendefinisikan widget RecipeGridCard berbasis StatelessWidget yang berfungsi menampilkan item resep dalam bentuk kartu pada tata letak grid. Widget ini menggunakan komponen Card dengan clipBehavior: Clip.antiAlias agar sudut foto terpotong rapi mengikuti lengkungan kartu, serta InkWell untuk mengarahkan pengguna ke halaman DetailPage saat kartu ditekan. Pada bagian atas kartu, kombinasi Expanded dan Stack digunakan untuk menampilkan foto resep secara penuh melalui RecipeImage sekaligus menempatkan tombol favorit di pojok kanan atas yang terhubung dengan FavoriteProvider, sedangkan bagian bawah menampilkan nama resep yang dibatasi satu baris beserta informasi rating dan waktu memasak.

10. Langkah C.2 — HomePage dengan list dan grid

Ganti seluruh isi home_page.dart, namun tombol pengaturan tetap dipertahankan.

Kode ini mengubah HomePage menjadi StatefulWidget untuk mengelola variabel state lokal _isGrid menggunakan fungsi setState() saat tombol ikon tampilan pada AppBar ditekan. Berdasarkan nilai _isGrid, bagian body halaman akan beralih merender daftar resep dalam format satu kolom menggunakan ListView.builder atau format kartu dua kolom beraspek 3 / 4 menggunakan GridView.builder.

11. Langkah C.3 — Menghitung ukuran kartu

- Menghitung Lebar Kartu:

Lebar kartu = (W_layar - Padding Horizontal - (Jumlah Kolom - 1) * crossAxisSpacing) / Jumlah Kolom

Lebar kartu = (360 - 16 - (2 - 1) * 8) / 2 = (360 - 16 - 8) / 2 = 336 / 2 = 168 dp

- Menghitung Tinggi Kartu:

Tinggi kartu = Lebar kartu / childAspectRatio

Tinggi kartu = 168 / (3 / 4) = 168 * (4 / 3) = 224 dp
Yang dihitung Hasil
Lebar kartu (dp) 168 dp
Tinggi kartu (dp) 224 dp

Pertanyaan Analisis

14. Pada skenario 3 dan 4 Langkah D.2, status favorit tetap sama walaupun tampilan berganti dari grid ke list. Padahal RecipeGridCard dan RecipeTile adalah dua widget yang berbeda. Jelaskan mengapa, dengan mengaitkannya pada Modul 6.

Status favorit tetap sama ketika tampilan berganti antara grid dan list karena data favorit tidak disimpan di dalam state lokal masing-masing widget kartu, melainkan dikelola secara terpusat sebagai app state menggunakan FavoriteProvider (ChangeNotifier) yang dibagikan ke seluruh pohon widget melalui ChangeNotifierProvider seperti yang telah dipelajari pada Modul 6. Baik RecipeGridCard maupun RecipeTile sama-sama memantau dan membaca sumber data tunggal dari context.watch<FavoriteProvider>().isFavorite(recipe), sehingga perubahan status favorit pada salah satu tampilan otomatis tercermin pada tampilan lainnya.

15. Di dalam loadingBuilder terdapat baris if (loadingProgress == null) return child; Apa yang akan tampil jika baris tersebut dihapus? Jelaskan alasannya.

Jika baris if (loadingProgress == null) return child; dihapus, maka gambar foto resep tidak akan pernah muncul di layar dan aplikasi akan terus-menerus menampilkan indikator loading (CircularProgressIndicator) meskipun proses pengunduhan foto dari server telah selesai. Hal ini terjadi karena Flutter menandai selesainya pengunduhan gambar dengan mengirimkan nilai loadingProgress bernilai null, sehingga tanpa kondisi pengecekan tersebut fungsi loadingBuilder tidak akan pernah mengembalikan widget child (gambar asli) dan terus merender animasi pemuatan.

16. Hitung berapa pixel foto thumbnail yang di-decode dengan dan tanpa cacheWidth: 168, jika foto asli dari server berukuran 1200 x 800 pixel. Apa akibatnya bagi memory ketika datanya menjadi 50 resep pada Modul 8?

Tanpa cacheWidth, foto berukuran asli 1200 x 800 pixel akan di-decode penuh sebanyak 1200 x 800 = 960.000 pixel per foto, sedangkan dengan cacheWidth: 168 dan rasio aspek yang sama (3 : 2), tinggi hasil decode menjadi 168 x (800 / 1200) = 112 pixel sehingga totalnya hanya 168 x 112 = 18.816 pixel per foto. Ketika jumlah data resep bertambah menjadi 50 resep pada Modul 8, pemuatan tanpa cacheWidth akan membebani RAM sebesar 50 x 960.000 = 48.000.000 pixel yang berisiko menyebabkan lag saat scrolling hingga crash pada perangkat berspesifikasi rendah, sedangkan dengan cacheWidth: 168 total beban memorinya hanya 940.800 pixel sehingga aplikasi tetap ringan dan responsif.

17. Logo memakai Image.asset, sedangkan foto resep memakai Image.network. Mengapa logo tidak sebaiknya diambil dari internet, dan mengapa foto resep tidak dimasukkan ke asset?

Logo aplikasi sebaiknya menggunakan Image.asset karena ukurannya kecil, bersifat statis, dan merupakan bagian dari identitas utama antarmuka sehingga harus dapat dimuat secara instan tanpa jeda jaringan maupun risiko gagal tampil saat perangkat tidak terhubung ke internet. Sebaliknya, foto resep jumlahnya sangat banyak, berukuran besar, serta bersifat dinamis mengikuti penambahan data dari server/API, sehingga memasukkannya ke dalam asset lokal akan membuat ukuran file instalasi aplikasi membengkak dan menyulitkan pembaruan konten tanpa harus merilis ulang versi aplikasi.

Latihan

18. Latihan 1 (wajib) — Filter cuisine

Tambahkan deretan ChoiceChip di bawah AppBar Home yang dapat digeser ke samping: "Semua" ditambah setiap cuisine yang ada di data. Memilih sebuah chip hanya menampilkan resep dengan cuisine tersebut, baik di mode list maupun grid.

  • Tambahkan state String? _cuisine di _HomePageState. Nilai null berarti semua cuisine.
  • Ambil daftar cuisine dari data, bukan ditulis manual, misalnya dummyRecipes.map((r) => r.cuisine).toSet().
  • Ubah body menjadi Column: deretan chip di dalam SizedBox(height: 56) berisi ListView horizontal, lalu Expanded berisi list atau grid.
  • Kirim data yang sudah difilter ke _buildList() dan _buildGrid().

Penyesuaian pada lib/pages/home_page.dart ini menambahkan variabel state lokal String? _cuisine di dalam _HomePageState untuk menyimpan kategori masakan yang dipilih pengguna, dengan nilai awal null yang menampilkan seluruh data resep. Daftar kategori cuisine diekstrak dari dummyRecipes menggunakan .map((r) => r.cuisine).toSet() lalu ditampilkan dalam bentuk deretan ChoiceChip di dalam ListView horizontal berbungkus SizedBox(height: 56) di bagian atas Column. Ketika salah satu chip dipilih, fungsi setState() memperbarui nilai _cuisine dan menyaring daftar resep yang diteruskan ke dalam widget Expanded berisi _buildList maupun _buildGrid, sehingga penyaringan bekerja secara sinkron pada kedua mode tampilan tanpa menyebabkan overflow tata letak.

19. Latihan 2 (wajib) — Halaman Favorit yang lebih rapi

Ubah halaman Favorit sehingga:

  • memakai ListView.separated dengan Divider di antara item;
  • setiap baris menampilkan thumbnail foto memakai RecipeImage;
  • item dapat digeser ke kiri untuk menghapusnya dari favorit (Dismissible), disertai SnackBar berisi nama resep yang dihapus.

Dismissible wajib diberi key yang unik dan stabil. Gunakan ValueKey(recipe.id), bukan index. Jika kalian sudah mengerjakan Latihan 2 Modul 6 (tombol hapus semua), pertahankan tombol tersebut.

Pembaruan pada file lib/pages/favorite_page.dart ini mengganti daftar statis menjadi ListView.separated dengan pemisah Divider di antara setiap baris resep favorit, serta menambahkan thumbnail foto berukuran 56x56 dp menggunakan widget RecipeImage di bagian leading pada ListTile. Setiap item dibungkus oleh widget Dismissible dengan ValueKey sebagai kunci unik yang stabil serta arah geser ke kiri, sehingga ketika pengguna menggeser item untuk menghapusnya dari FavoriteProvider, aplikasi langsung menampilkan notifikasi SnackBar berisi nama resep yang dihapus sambil tetap mempertahankan fitur tombol hapus semua pada AppBar.

20. Latihan 3 (bonus) — Foto yang mengecil saat di-scroll

Ubah halaman detail menjadi CustomScrollView dengan SliverAppBar (pinned: true, expandedHeight: 260) yang menampilkan foto resep sebagai background FlexibleSpaceBar. Bagian porsi dan judul "Bahan" diletakkan di SliverToBoxAdapter, dan daftar bahan memakai SliverList.builder.

Untuk foto di SliverAppBar, gunakan package cached_network_image agar foto tersimpan di disk dan tidak diunduh ulang ketika aplikasi dibuka kembali:

cached_network_image versi 4 membutuhkan Flutter 3.44 atau lebih baru. Periksa versi Flutter kalian dengan flutter --version.

Pembaruan pada file lib/pages/detail_page.dart ini mengganti tata letak halaman detail menjadi CustomScrollView dengan SliverAppBar yang memuat foto resep di dalam FlexibleSpaceBar menggunakan CachedNetworkImage, sehingga foto dapat mengecil secara mulus saat layar digulir sekaligus tersimpan di cache disk agar tidak diunduh ulang. Bagian informasi kategori resep, kartu pengatur jumlah porsi, total kalori, dan judul Bahan diletakkan di dalam SliverToBoxAdapter, sedangkan daftar bahan-bahan resep dirender secara efisien menggunakan SliverList.builder di bawahnya.

D. Kesimpulan

Berdasarkan rangkaian praktikum Modul 7 yang telah dilaksanakan, seluruh fitur manajemen list, grid, gambar, dan asset berhasil diimplementasikan dengan baik pada aplikasi ResepKu. Penggunaan ListView.builder dan GridView.builder memungkinkan aplikasi merender daftar resep secara efisien dalam dua mode tampilan berbeda dengan status favorit yang tetap tersinkronisasi melalui FavoriteProvider. Selain itu, penerapan RecipeImage dengan loadingBuilder, errorBuilder, dan pembatasan dimensi cacheWidth terbukti menjaga stabilitas antarmuka tanpa memunculkan pesan error saat perangkat berada dalam kondisi offline sekaligus menghemat konsumsi memori secara signifikan.

Penyempurnaan antarmuka melalui latihan mandiri juga berhasil meningkatkan pengalaman pengguna secara keseluruhan. Penambahan deretan ChoiceChip mempermudah penyaringan resep berdasarkan kategori masakan pada mode list maupun grid, sementara pembaruan halaman favorit menggunakan ListView.separated dan Dismissible memberikan interaksi penghapusan item yang intuitif disertai umpan balik SnackBar. Di sisi lain, penerapan CustomScrollView, SliverAppBar, dan cached_network_image pada halaman detail menghasilkan animasi penyusutan foto yang halus saat layar digulir serta mempercepat pemuatan gambar melalui penyimpanan cache lokal.
